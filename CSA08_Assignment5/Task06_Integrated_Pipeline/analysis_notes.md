# B1 – Implementation and Experimental Investigation

## B1.1 Before and after cleaning
The input CSV intentionally includes `NA`, blank PM2.5, a negative PM2.5 value, an extreme PM2.5 value, a duplicate station/date/hour row, and Fahrenheit temperatures. Run `main.py`; inspect `data/air_quality.csv`, `output/cleaned_air_quality.csv`, and `execution_report.txt`. Missing pollutant cells remain null, invalid-range measurements are excluded from analysis, duplicates are discarded, and Fahrenheit temperatures are converted to Celsius.

## B1.2 Compare with design
The implementation follows the planned station/date/hour key and unit conversion. For demonstration, invalid pollutant readings are stored as null rather than deleting the entire row, so valid PM10/NO2/temperature values from that observation remain usable. The sanity thresholds are illustrative and must be checked against the actual sensor specification.

## B1.3 Store and query
The program creates `output/air_quality.db`, uses `executemany` for station and reading inserts, and runs parameterised queries for Adyar's October average, station averages and worst hours. A daily station summary is also generated using SQL `GROUP BY`.

## B1.4 Visualise
Four charts are saved in `output/`:
- `pm25_monthly_trend.png`: daily mean trend; peaks indicate days requiring closer review.
- `station_comparison.png`: station-level mean comparison; higher bars indicate locations with higher average PM2.5.
- `temperature_vs_pm25.png`: scatter plot; the sample is small, so it cannot establish causation.
- `worst_hours.png`: mean PM2.5 by hour; interpret only hours represented in the sample.
